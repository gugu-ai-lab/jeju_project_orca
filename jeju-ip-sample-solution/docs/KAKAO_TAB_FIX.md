# 왼쪽 카카오맵 탭 수정·실제 SDK 검증

## 원인과 수정

지도 본체와 로딩용 임시 DOM이 같은 `mapContainerRef`를 사용했다. SDK가 로딩용 DOM에 지도를 생성한 뒤 `ready` 상태가 되면 해당 DOM이 제거되어 본체 지도 영역은 빈 상태로 남았다.

`JejuMythExplorerMap.jsx`에서 지도 DOM 참조를 하나로 유지하고 로딩용 영역은 짧은 텍스트로 바꿨다. 공유 SDK 로더가 이미 준비한 `maps`를 받아 초기화하여 중복 `maps.load` 대기도 제거했다.

SVG 그림·CSS·핀 데이터·이야기·날씨 서버·퍼즐·AI·Supabase·사진 기능은 수정하지 않았다. 환경변수와 인증키도 읽거나 변경하지 않았다. 기존 키가 정상 설정된 5181 서버를 그대로 사용했다.

## 실제 브라우저 검증

`scripts/test-kakao-tab-browser.mjs`에서 모의 SDK가 아닌 실제 카카오 SDK를 사용했다. SDK 생성자는 관찰용으로만 감쌌으며 원본 지도·마커 객체를 그대로 생성한다.

- 왼쪽 카카오맵 탭에서 지도 DOM과 6개 실제 마커 표시.
- 실제 지도 화면 좌표에 마우스로 혼인지·돌문화공원 마커를 클릭하여 사용자 선택 이벤트 검증.
- 각 장소 선택에 맞춰 이야기 카드·실제 기상청 예보·길찾기 목적지 변경 확인.
- 실제 마커 좌표와 목적지 좌표 일치 확인.
- 지도 이동 완료 이벤트 뒤 선택 위치가 화면 중심에서 1픽셀 이내인지 확인. SDK의 화면 좌표 반올림 때문에 반환 중심 위경도는 마커 좌표와 미세하게 다를 수 있으므로 픽셀 기준과 전달한 이동 좌표를 함께 검증했다.
- SVG 탭으로 복귀 후 SVG 마크업이 처음과 정확히 같음을 확인.
- 카카오맵으로 재진입해 지도와 마커 6개 유지 확인.
- 페이지 실행 오류 0개, 실제 OpenAI·Supabase 요청 0회.

전체 자동 테스트 55개 통과, 빌드 성공, 린트 오류 없음. 기존 관광·국가유산 화면 경고 4개 유지.

앞선 `SELECTED_PLACE_GUIDE.md`에 기록된 실제 지도 표시 제한 이후 키 설정이 정상화됐으며, 이번 수정으로 왼쪽 탭 표시 문제까지 실제 SDK로 검증했다.

미리보기: `http://127.0.0.1:5181/`

브라우저 재검증 예시:

```sh
PLAYWRIGHT_MODULE_PATH=/tmp/jeju-starter-browser-check/node_modules/playwright/index.mjs node scripts/test-kakao-tab-browser.mjs
```

이 검증은 카카오·기상청에 실제 읽기 요청을 수행한다. 키를 출력하지 않으며 OpenAI·Supabase 요청은 차단한다.
