# 국가유산 사진 연결 검증 (2026-11-02)

## 원인

기존 `SearchKindOpenapiList.do` 목록 응답에는 이미지 URL이 없었다. 서버는 이름·종목·시군구·좌표만 반환하고 `Heritage.jsx`도 `ItemCard`에 `image`를 전달하지 않았다. 공통 카드는 이미지 prop가 없으면 회색 플레이스홀더를 표시하는 정상 동작이었다.

국가유산청 `SearchKindOpenapiDt.do` 상세 응답에는 대표 `imageUrl`이 있고, `SearchImageOpenapi.do`에는 사진별 URL·설명·이용허락 코드가 있다. 같은 유산의 종목/지정번호/시도 코드로 직접 조회하므로 TourAPI의 이름 유사도 매칭은 사용하지 않았다. XML 지정번호의 선행 0을 보존한다.

## 보호 및 실패 처리

- 위 두 유산 번호와 사진 번호를 명시적으로 승인 목록에 등록했다. 이름이 같은 다른 장소나 미검토 사진은 연결하지 않는다.
- 사진 API의 세 가지 식별번호 일치, 승인된 정확한 사진 경로, 공식 호스트, `A/F` 코드가 모두 맞아야 URL을 반환한다.
- 원본 HTTP URL은 실제 HTTPS 응답을 확인한 뒤 HTTPS로 전달한다.
- 사진 API 실패·조건 변경·미검토 항목은 이미지 없이 목록을 반환하여 기존 플레이스홀더를 유지한다.
- 성공 사진 메타데이터는 5분 캐시한다. 전체 479개 유산 사진 조사나 자동 확대 적용은 하지 않았다.
- Gemini 브랜치·공통 ItemCard·즐겨찾기·에이전트는 수정하지 않았다. Codex의 Heritage 페이지에는 이미지 prop와 출처 링크만 연결했다.
